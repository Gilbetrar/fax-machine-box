# Adversarial QA report — issue #25 (2026-07-09)

Deep adversarial, ground-up verification of every generated cut file, per the issue #25
mandate ("treat every generated output as guilty until proven correct"). Run as a two-pass
red-team: **8 independent adversarial reviewers in pass 1** (render-based visual ×2,
independent geometry re-derivation, assembly simulation, engrave-layer audit, provider
conformance, bed-size portability, unbiased blind-spot sweep), fixes, then **4 verification
reviewers in pass 2** (regression diff vs pass-1 ground truth, visual re-inspection,
docs-consistency, naive-user README walkthrough). Full per-critic findings with evidence:
`scratch/qa-critics/*/FINDINGS*.md`; rendered evidence: `scratch/qa-renders/` (current) and
`scratch/qa-renders-pass1/` (pre-fix archive).

## Bottom line

**The cut geometry itself is clean and independently verified.** All 23 part blanks and
every measured feature (openings, slots, hole rows, finger counts/pitches, magnet holes,
pivot, grip slots, mirrors) match an independent re-derivation from DESIGN.md + config.py
to <0.01mm; all 682 cut subpaths are closed; kerf compensation is correct at the
fit-determining flats for both providers (early "under-compensation" reports were bbox
artifacts from corner-relief arcs — refuted by direct flat-to-flat measurement); no
duplicate/coincident cut lines; Ponoko conformance verdict on the three upload sheets:
**accept, conditional only on the standard confirm-size dialog**. LightBurn/hobby verdict
on the sheets: accept.

**The defects found were around the geometry, not in it**: label hygiene on standalone
files, coupon usability, doc/spec honesty, bed-size portability plumbing, one stale-file
hazard — and ONE genuine Clark-class visual defect that is a design decision, not a bug
fix, and is documented as the top open item below.

## Fixed in this pass (all regression-guarded by new tests; suite 200 → 217 tests)

1. **Engrave-red part labels on standalone files** (the exact defect class that broke
   trust in issue #25). drawer/lids/outer_shell/coupon SVGs carried live un-outlined
   `<text>` filled `rgb(255,0,0)` — a hobby laser burns the words into the parts. Fixed
   systemically: `src/faxbox/svglabels.py::enforce_reference_labels()` runs at every
   generator's write site (both providers); labels are gray + `data-purpose=
   "reference-label"`. Guard: two new tests ban red text fills across EVERY output SVG.
2. **Bed-size portability was a mirage** (Ben's explicit ask). Sheet size was hardcoded;
   any non-default bed required editing source. Now: `PROVIDERS[...]["sheet_width"/
   "sheet_height"]`, `generate_layout(provider=…, sheet_width=…, sheet_height=…,
   margin=…, spacing=…)`, `FAXBOX_SHEET_WIDTH/HEIGHT` env vars (kwarg > env > provider >
   default), loud failure on unknown provider, and a tested README procedure. 10 new tests
   incl. exact-minimum and too-small boundaries. Verified end-to-end by a naive-user
   walkthrough agent at 400×300.
3. **Thickness coupon couldn't read the top of the stock band.** Gauges were
   3.05/3.175/3.30 while the documented ply band is 3.0–3.4 — silent exactly where finger
   joints get tightest. Now five gauges 2.95/3.05/3.175/3.30/3.40, all verified
   physical-width == label after burn compensation.
4. **Ponoko calibration coupon was unusable as shipped**: label-stripping left its four
   magnet gauge holes (0.15mm steps) indistinguishable. Now 1/2/3/4 engraved tick marks in
   ascending size order (survive label stripping; verified in renders + tests).
5. **Stale-sheet hazard**: `generate_layout` didn't purge previous sheets, so a rebuild
   for a smaller bed followed by a default rebuild left extra cut-ready-looking
   `sheet_N.svg` files on disk (found live in pass 2). Both layout paths now purge before
   writing; regression test added. Two stale orphan artifacts (`retention_coupon.svg` —
   no generator on main, PR#22-era; 3-slot-era `kerf_coupon.pdf`) archived to
   `scratch/archived-orphans/`.
6. **New guard-test class: red-vs-blue clearance** (`tests/test_engrave_cut_clearance.py`)
   — the check whose absence let the FAX MACHINE defect ship. Engraving must clear cut
   features by ≥1mm on every part; the two deliberate exceptions (faceplate registration
   outline flush-by-design; the open right-wall collision) are pinned by their own
   assertions so they cannot be silently forgotten or silently "fixed".
7. **Docs/spec honesty sweep** (DESIGN.md, README, config comments) — every wrong number
   found by measurement is corrected: bay gap 0.475 (was "~1.1"), drawer external 221.775
   (was 221.2), magnet-to-edge 34.5mm on the drawer back (was "~39"), turn-button margin
   5.3mm (was 6.3), capture-travel 2.4mm (was 2.7), interior 212.25 comment (was 211.65),
   FINGER_PLAY honestly covers stock ≤~3.275mm (the "covers 3.0–3.4" claim was false —
   thicker stock requires coupon recalibration), top-panel hole rows open the visible top
   edge (panel fixity depends on the specified glue-up — now stated in DESIGN, README),
   magnet flush-install requirement (a recessed 2mm pair collapses pull ~4–6×; README
   shopping list + install steps now match DESIGN), lid-slot mouth is a 0.11/0.15mm
   kerf-offset pair, not a coincident double-cut (Ponoko's doubled-line objection
   inapplicable), largest DRAWN part is 304.96×165.26mm (not 298.45 — that's the interior
   figure), minimum viable bed 324.96×185.26mm.
8. **README additions**: rebuild-for-any-bed procedure (with the 300×200 impossibility
   stated), faceplate flip instruction at glue-up (engraved registration face must become
   the glue face), never-lift-by-lid + fragile rear-wall-web handling warnings, magnet
   coupon correctly described as burn-compensated, render-QA doctrine.
9. **Repeatable render QA harness**: `scripts/qa_render.py` (239 PNGs: whole-sheet,
   per-part, per-corner, thick variants) — documented in README as mandatory after any
   generator change.

   The shelf finger-hole row (Z 61.9–65.1) runs through the letters' waist (text center

   `scratch/qa-renders/sheet_2/shell-right-wall_thick.png`. Options:
   (a) **remove the pixel text now** — art/FACES.md maps this wall to full-panel art

   (b) shrink to pixel size ~3.5 and recenter in the clear band right of the divider
   column and above the shelf row (fits X 84–294, Z 67–118);
   (c) accept holes-through-letters (shelf finger end-grain will show through the logo).
   Interim state: pinned by `test_right_wall_known_collision_still_present`.
2. **Game-component acceptance spec is missing** (blind-spot #1): no paper/pen/stack
   dimension exists anywhere in the repo — the box is verified against itself, not against
   the game. Need from Ben: pre-cut paper W×H, stack height, longest pen/pencil. Then a
   3-line test closes the loop.
3. **Turn-button bolt tail protrudes ~4–5mm into the paper compartment** at Y-center,
   Z=110 (mid-height of a leaning paper stack). Pivot Z is boxed in by the blocking
   geometry (must sit in ~104.7–112.5), so relocation can't fix it; it's inherent to a
   through-bolt. Accept (paper leans on a smooth nyloc), or spec a lower-profile

4. **Drawer/lid ergonomics accepted as v1** (no out-stop on drawers, lid pulls out
   pre-turn-button) — README warnings added; gift-recipient behavior (grab the lid) is
   the residual risk.

## Accepted / cosmetic (documented, deliberately not changed)

- 78 one-micron degenerate segments on cut polylines (interior vertices; no re-pierce, no
  dwell; below any service's resolution).
- Three stroke widths across the deliverable set (0.0762 sheets / 0.16 standalone / 0.20
  ponoko coupon) — every service under consideration ignores or accepts them.
- Coupon gray titles overlap coupon cut features (reference-only text, never mapped to a
  laser op, throwaway parts).
- `ponoko/sheet_2.svg` is 789.2mm wide vs the 790mm workable max (0.8mm clearance) —
  inside spec; re-nesting for more margin would churn verified sheets.
- Sub-kerf parallel pair at each lid-slot mouth (0.11/0.15mm apart) burns as one channel —
  by design, now correctly described in DESIGN.md.
- Colors are `rgb()` functional notation: verified fine for Ponoko (per-color op
  assignment) and LightBurn (palette match by resolved value).
